# Antigravity Memory Skill — Technical Documentation

Audience: agents and developers integrating, debugging, or extending this skill.
User-facing overview: see `README.md` (Vietnamese). Agent-facing behavior contract:
see `SKILL.md`. This document describes only what the spec defines; it does not
invent additional surfaces.

## 0. Honesty limits (binding)

These limits also appear in `SKILL.md` and `README.md` and must not be softened
in downstream documentation:

- The skill does **not** guarantee that any user request comes out exactly as the
  user intended. It maximizes intent-match via: (a) acceptance criteria extracted
  at session start, (b) a clarification loop when the request is
  ambiguous/irreversible/costly, (c) a verification gate before reporting done
  (run the project's real checks, compare against the criteria), and (d) a lesson
  recorded whenever output misses intent.
- The skill **cannot** read a model's hidden chain-of-thought. The substitute is
  the "thinking journal": for tasks of more than ~3 steps the agent MUST write
  its reasoning to a file BEFORE acting (goal, criteria, hypotheses, options
  considered and rejected with reasons, assumptions, verification plan) and
  update it after finishing. The journal is what gets re-read and audited —
  never claim otherwise. The journal is only as good as what the agent writes
  into it; it is an agent-authored record, not an extraction of hidden reasoning.

## 1. Architecture overview

Pipeline: **capture → tiered Markdown store → retrieval → lessons/journal/gates**.

1. **Capture.** The agent records facts, decisions, and session summaries through
   the CLI (`save`, `lesson-add`, `journal-start`/`journal-note`/`journal-close`),
   and through conversation procedures (`/remember`, `/recall`, `/lesson` — see
   §6). Session boundaries are captured by hooks (§5): SessionStart prints a
   briefing, Stop appends a session-summary skeleton.
2. **Tiered Markdown store.** One Markdown file per entry, organized in numbered
   tiers (§2). A generated router (`00_MEMORY_ROUTER.md`, max 40 lines) is the
   cheap, always-loaded entry point; full entry files are read on demand
   (progressive disclosure).
3. **Retrieval.** `search` ranks entries with the BM25-lite scoring in §4;
   `context` returns the router plus top entries by category priority;
   `lesson-check` matches lessons by error signature against the current
   error/situation text.
4. **Lessons and journals.** Lessons (§3) are recalled by trigger before similar
   work and must be written before retrying after a failure where possible, and
   always before reporting done after a failure. Journals (§3) are the
   pre-action reasoning record for multi-step tasks.
5. **Gates.** Before reporting done, the agent runs the verification gate: the
   project's real checks, compared against the acceptance criteria recorded at
   session start. Ambiguous, irreversible, or costly requests go through the
   clarification loop first.

Runtime constraints: zero dependencies, Node.js >= 18 standard library only, no
network calls anywhere in `scripts/`. Local-first, no telemetry.

## 2. Storage layout and entry schema

### 2.1 Store root resolution (in order)

1. `--dir` flag
2. `AGMEM_DIR` environment variable
3. `<cwd>/.agents/memory`, IF a `.agents/` directory exists in cwd
4. `$HOME/.antigravity-memory`

For a project install, the user/agent sets `AGMEM_DIR` to the project
`.agents/memory`, or the hook scripts pass `--dir`.

### 2.2 Layout

```
<store>/
  00_MEMORY_ROUTER.md            # GENERATED by `memory.js index`. Never hand-edit (regeneration overwrites).
  01_user-profile/*.md           # user facts, preferences
  02_episodic/*.md               # session summaries, decisions, work logs
  03_semantic/*.md               # durable knowledge, project facts, conventions
  04_procedural-lessons/*.md     # lessons from mistakes (schema §3)
  05_thinking-journal/*.md       # thinking journals (schema §3)
  index.json                     # search index, rebuilt automatically when stale (see §4.3)
```

The router is GENERATED, max 40 lines, with sections in this order:
`# Memory Router`, `## User` (top user/preference facts, 1 line each),
`## Active projects`, `## Key decisions`, `## Lessons — triggers` (1 line each:
`trigger → file`), `## Open threads`. Truncation is by importance, then recency.
Router lines point at entry files; the agent reads the full file on demand.

### 2.3 Entry file format (one Markdown file per entry)

```markdown
---
id: m_<10 hex chars>
category: user | preference | project | decision | lesson | fact | episodic | other
tags: [tag1, tag2]
source: user | tool-output | file-path | url | session
confidence: verified | user_stated | inferred
importance: 1..5   # 5 = user-asserted or load-bearing; 1 = trivial
created_at: <ISO 8601>
updated_at: <ISO 8601>
access_count: 0
error_signature: ""   # lessons only: comma-separated trigger substrings, lowercase
trigger: ""           # lessons only: short situation description
prevention_check: ""  # lessons only: command or checklist item to run first next time
---

<body: one self-contained fact, or the lesson/journal content>
```

Rules:

- `id` = `m_` + 10 lowercase hex chars from `crypto.randomBytes(5)`.
- Body max 2000 chars for ordinary entries (split longer facts).
- Duplicate (same normalized body) must NOT create a second file: update
  tags/source/`updated_at` instead.
- Writes are atomic (temp file + rename). Corrupt entry files are skipped with
  a stderr warning, never crashing the whole command.

## 3. Lessons and thinking journals

### 3.1 Lesson file

A lesson lives in `04_procedural-lessons/`, uses the entry format in §2.3 with
category `lesson`, and its body carries these mandatory sections:

```
Title: <short name>
What: <symptom / what went wrong>
Why: <root cause, evidence-backed, one sentence>
Where: <file / command / tool>
Lesson: <what to do differently>
Trigger: <situation pattern that should recall this lesson>
Prevention: <exact check/command to run before similar work>
```

Capture triggers — the agent MUST `lesson-add` when: a test/lint/build fails, a
tool errors, output is wrong, or the user corrects the agent. The lesson is
written BEFORE retrying where possible, and always before reporting done after
a failure.

### 3.2 Thinking journal

Journals live in `05_thinking-journal/` as `<YYYY-MM-DD>-<slug>.md` with
mandatory sections: `## Goal`, `## Acceptance criteria`, `## Hypotheses`,
`## Options considered (and rejected, with reason)`, `## Assumptions`,
`## Verification plan`, `## Progress notes`, `## Outcome`, `## Lesson link`.

Protocol: task > ~3 steps → `journal-start` (goal + criteria + options) BEFORE
acting, `journal-note` after each major step, `journal-close` (outcome + lesson
link) at the end.

### 3.3 Forgetting policy (never auto-delete)

Implemented as an `index --stale` listing, NEVER auto-delete: flag entries with
importance ≤ 2 AND no access in 180 days as stale candidates for user review.
NEVER flag or delete entries with confidence `user_stated` and importance ≥ 4
without explicit user confirmation.

## 4. Retrieval scoring (summary)

Implemented in `scripts/memory.js` (`search`). Defaults below; the full
justification lives in `docs/math-model.md`.

- **Tokenize:** lowercase, split on non-alphanumeric, drop tokens of length < 2,
  drop a small stopword list (EN + VI common words).
- **Match:** a query token matches a doc token if equal OR the doc token
  startsWith the query token.
- **BM25-lite:** `k1 = 1.2`, `b = 0.75`,
  `idf = ln(1 + (N - df + 0.5) / (df + 0.5))`.
- **Tier weights:** lesson 1.6, user 1.5, preference 1.4, decision 1.2,
  project 1.1, fact 1.0, episodic 0.9, other 0.8.
- **Importance factor:** `(0.7 + 0.3 * importance / 5)`.
- **Recency bonus:** `0.5 * 2^(-age_days / 60)` (60-day half-life).
- **Exact-phrase bonus:** `+2.0` if the normalized query string appears in
  normalized content.
- **Final score:**
  `score = BM25 * tier_weight * importance_factor + recency_bonus + phrase_bonus`.

Behavior:

- `search` returns top N (default 8) with score and coverage.
- `context` returns the router plus top entries by category priority:
  user, preference, project, decision, lesson, fact, episodic, other.
- `lesson-check <text>`: returns lessons whose `error_signature` substrings
  (case-insensitive) appear in the text, ranked by number of matched
  substrings, then importance.

### 4.1 Token budget

- Router ≤ 40 lines (hard cap in `index`).
- Rule file < 2 KB (keeps the 20k aggregate budget healthy; see §6.2).
- `context` default max 30 items; `search` default 8.

### 4.2 Index

`index.json` holds per-entry `{id, file, category, tags, tokens, importance,
updated_at, access_count, error_signature}`. If any entry file is newer than
`index.json`, rebuild from files (and rewrite `index.json`). Search must work
even with no index.

## 5. Hooks

Configured in `hooks/hooks.json` with two events:

| Event | Handler behavior |
|---|---|
| `SessionStart` | Runs the session-start handler, which prints the router/context briefing to stdout. |
| `Stop` | Runs the session-stop handler, which appends an episodic session summary skeleton. |

Handler contract (mandatory):

- MUST exit 0 even on error.
- MUST tolerate unknown stdin payloads (read stdin if present, ignore parse
  failures).
- MUST be fast and non-interactive.

**No PostToolUse hook is shipped.** Its payload/matcher semantics are not
verified for this build, so no PostToolUse hook config is included; it is
documented here as optional only, not implemented.

**Merge strategy (install.sh):** install.sh MERGES `hooks.json` — it backs up
the existing file to `hooks.json.bak` first and never overwrites it outright.
If hooks are not running after install, check the merged `hooks.json` first
(see §8).

**Unverified detail (read before shipping to a new build):** the official
docs verify the event names (`SessionStart`, `Stop`), the file locations
(`.agents/hooks.json`, `~/.gemini/config/hooks.json`), and the handler
contract (stdout briefing, exit 0, tolerate unknown payloads) — but the exact
per-entry field schema of `hooks.json` (this skill uses a `command` field per
entry, following the most common convention) is NOT quoted verbatim in the
sources checked. If hooks do not fire after a correct-looking install, open
your build's Settings → Customizations → Hooks panel and compare its
expected entry format with the merged file before assuming the handlers are
broken.

## 6. Antigravity integration formats

### 6.1 Skill

- Skill folder: `<dest>/<skill-name>/SKILL.md` with frontmatter `name`
  (lowercase/hyphens) and `description` (REQUIRED — this is what the agent sees
  when deciding to apply the skill).
- Workspace install: `<workspace>/.agents/skills/antigravity-memory/`.
- Global install: `~/.gemini/config/skills/antigravity-memory/`.

### 6.2 Rules

- Rule file: `rules/memory-always-on.md`, YAML frontmatter `trigger: always_on`
  + `description`. Keep it SHORT (aim < 2 KB; official caps: 24,000 bytes/file,
  20,000-token aggregate across always_on + global rules).
- Installed to `<workspace>/.agents/rules/` or `~/.gemini/config/rules/`.

The skill only takes effect when the agent honors the always_on rule and the
hooks run. If either is ignored, the memory store is neither loaded nor
written — see troubleshooting (§8).

### 6.3 Slash commands (procedures, not command files)

Implemented as SKILL.md procedures + CLI subcommands. Do NOT invent an
Antigravity command-file format (Flashmind's `.toml` commands are Gemini CLI,
not Antigravity):

- `/remember` = save key facts + close journal.
- `/recall` = context + search.
- `/lesson` = lesson-add.

### 6.4 No workflows

Do NOT build on workflows. Official workflow docs show a post-2026-10-19
replacement that is unverified. No workflow files ship in this skill.

### 6.5 Relation to built-in features

- `/learn` (built-in, reviewable rule/skill proposals) and `/resume` (thread
  continuation) are **complementary, not replacements** for this skill.
  `/learn` proposes durable rules/skills for review; this skill is the
  persistent, queryable record those proposals draw on and live alongside.
  `/resume` continues a thread; this skill supplies cross-thread memory that
  survives beyond any single thread.

## 7. CLI reference

Single entry point agents call: `scripts/memory.js`. `scripts/lessons.js` and
`scripts/journal.js` are library modules used by `memory.js`. All subcommands
print plain text to stdout, errors to stderr, and exit non-zero on failure.

```
node scripts/memory.js <command> [args] [--dir <path>]
```

| Command | Behavior |
|---|---|
| `context [--max-items N]` | Print router + top entries by category priority (default max 30 items). |
| `search <query> [--limit N] [--category C]` | Ranked entries with scores (default limit 8). |
| `save --content "..." [--category C] [--tags a,b] [--source S] [--confidence C] [--importance N]` | Save one entry; duplicates update instead of duplicating. |
| `get <id>` | Print one entry by id. |
| `list [--category C] [--limit N]` | List entries, optionally filtered. |
| `update <id> [--content ...] [--tags ...]` | Update an entry. |
| `delete <id>` | Delete an entry. |
| `lesson-add --title ... --what ... --why ... --where ... --lesson ... --trigger ... --prevention ... --signature "sub1,sub2"` | Add a lesson (§3.1). |
| `lesson-check <error-or-situation-text>` | Match lessons by error signature. |
| `journal-start --slug ... --goal ... --criteria ...` | Open a thinking journal (§3.2). |
| `journal-note --slug ... --note ...` | Append a progress note to a journal. |
| `journal-close --slug ... --outcome ... [--lesson <lesson-id>]` | Close a journal with outcome + optional lesson link. |
| `index` | Rebuild `index.json` + regenerate router (report line count; fail if > 40 lines after truncation — i.e. truncation must enforce ≤ 40). |
| `index --stale` | List stale candidates for user review only; never deletes (§3.3). |
| `--path` | Print the resolved store path (§2.1). |
| `--export` | Print the whole store as JSON. |
| `--version` | Print version `1.0.1`. |

All commands accept `[--dir <path>]` to override the store root (§2.1).
CLI exits non-zero on bad input.

## 8. Install / uninstall

### 8.1 Install

Prerequisites: Node.js >= 18, zero additional dependencies, no network calls
in `scripts/`.

`install.sh` copies ONLY this allowlist to the destination: `SKILL.md`,
`scripts/`, `rules/`, `references/`, `memory-templates/`, `hooks/`. Everything
else (`README.md`, `docs/`, `test/`, `install.sh`, `HANDOFF-REPORT.md`) stays
behind as documentation, not installed artifacts.

Destinations:

- Project: skill → `<workspace>/.agents/skills/antigravity-memory/`,
  rules → `<workspace>/.agents/rules/`.
- Global: skill → `~/.gemini/config/skills/antigravity-memory/`,
  rules → `~/.gemini/config/rules/`.

Hooks are merged, not overwritten: existing `hooks.json` is backed up to
`hooks.json.bak` first, then the SessionStart and Stop entries are merged in.
`install.sh` prints a version-drift warning (§9) telling the user to check
their build's skill panel if the skill is silently ignored.

Development/testing note: never touch a real `~/.gemini`, `~/.agents`, or real
Antigravity config during development or testing. Tests and install
verification use a sandboxed HOME (e.g. `HOME=/tmp/agmem-test-home`) and temp
dirs only.

### 8.2 Uninstall

There is no uninstaller flag defined in the spec; uninstall is manual removal
of exactly what install put in place:

1. Delete the installed skill directory (`antigravity-memory/` under
   `.agents/skills/` or `~/.gemini/config/skills/`).
2. Delete the installed rule file (`rules/memory-always-on.md`).
3. Remove the merged SessionStart/Stop entries from `hooks.json`
   (restore from `hooks.json.bak` if no other hooks were added afterwards;
   otherwise edit the entries out by hand).
4. The memory store itself is separate from the installed skill files and is
   NOT deleted by steps 1–3. Delete the store directory (§2.1) only if the
   user explicitly wants all recorded memory gone; that deletion is
   irreversible from the skill side.

## 9. Troubleshooting

### 9.1 Skill is silently ignored

Check in this order:

1. **Path (version drift).** Confirm the skill is installed under the CURRENT
   path for your build (`.agents/skills/`, `~/.gemini/config/skills/`), not an
   older path (see §10). A skill in the wrong directory is the most common
   cause of silent ignoring.
2. **Reload / new conversation.** Start a new conversation (or reload per your
   build's behavior) so the skill is picked up; a running session may not see
   a newly installed skill.
3. **Description.** Check `SKILL.md` frontmatter: `name` must be
   lowercase/hyphens and `description` must be present — the description is
   what the agent sees when deciding to apply the skill. A missing or vague
   description means the agent may never trigger it.

### 9.2 Hooks do not run

1. Check the merged `hooks.json`: confirm the SessionStart and Stop entries
   survived the merge and point at the installed handler scripts.
2. Check `hooks.json.bak`: if the merge went wrong, the pre-install backup is
   the known-good starting point — restore it and re-run install.
3. Confirm handler behavior: handlers must exit 0 even on error and tolerate
   unknown stdin payloads. A handler that crashes or blocks will look like
   "hooks don't run" from the outside; test the handler directly with empty
   stdin and with a malformed payload.
4. Confirm the store path resolves (§2.1): a SessionStart briefing can only
   print a router if the store it points at exists or can be created.

### 9.3 Router is empty

Run `index` explicitly. The router is generated, not hand-written: `index`
rebuilds `index.json` and regenerates `00_MEMORY_ROUTER.md` from the entry
files. An empty router with non-empty entry tiers means `index` has not run
(or failed) since the entries were added. Also verify `--path` resolves to
the store you expect — an empty router in the wrong store is the same symptom
as no memory at all. If `index` reports > 40 lines, truncation is failing and
must be fixed, not worked around by hand-editing the router.

### 9.4 Search finds nothing

Check that `index.json` is not stale relative to entry files (any entry file
newer than `index.json` triggers a rebuild), and remember search works even
with no index — so "no results" with entries present points at tokenization
or category filtering (`--category`), not at a missing index.

## 10. Version-drift notes

Antigravity skill/rule paths have drifted across versions. Current paths used
by `install.sh`:

- Skills: `<workspace>/.agents/skills/` and `~/.gemini/config/skills/`
- Rules: `<workspace>/.agents/rules/` and `~/.gemini/config/rules/`

Older guides use:

- `.agent/skills/` (singular `.agent`, not `.agents`)
- `~/.gemini/antigravity/skills/`

`install.sh` installs to the CURRENT paths and prints a drift warning telling
the user to check their build's panel if the skill is silently ignored. Do not
"fix" drift by installing to both old and new paths — that creates two copies
that diverge. Install to the path your build actually reads, and verify with
§9.1.

Also: workflow documentation changed after 2026-10-19 to an unverified
replacement; this skill ships no workflow files for that reason (§6.4).

## 11. Security

- **Local-first, no telemetry, no network in core.** `scripts/` makes no
  http/https/fetch/net/dns calls. Memory lives in local Markdown files.
- **Secret blocking.** On every `save`, `lesson-add`, and `journal-note`,
  content matching any of the following is refused (error naming the pattern
  class, never echoing the secret; exit non-zero; never logged):
  - long digit runs: 14–19 digits allowing spaces/dashes (card / national ID /
    account numbers);
  - Google API keys: `AIza` + 30+ base64url chars;
  - token formats: prefixes `sk-`, `pk-`, `ghp_`, `gho_`, `xoxa/b/p-` + 16+
    token chars;
  - PEM private key headers: `-----BEGIN ... PRIVATE KEY-----`;
  - password assignments: `password|passwd` followed by `:` or `=` and a value.
  Secret blocking prevents secrets from entering the store; it does not revoke
  a secret that was already exposed elsewhere.
- **Local files are NOT private from the model.** This is the critical caveat
  to the "local-first" claim: whenever memory files are read into an agent's
  context, their contents are sent to the model backend as part of that
  context, like any other context the agent reads. "Local-first" means no
  separate telemetry pipeline and no third-party memory service — it does NOT
  mean the model never sees the contents. Do not store anything in memory that
  you would not put in a prompt, and rely on §11 secret blocking only for the
  pattern classes listed above, not as a general confidentiality guarantee.
- **Do not store secrets by hand either.** Hand-editing an entry file bypasses
  CLI secret blocking; treat the pattern list above as the rule for manual
  edits as well.
